# Readiness and remaining work

Anteater is a prototype with earlier fixture validation. Its default kill switch remains on, and passive collection and application research are separately opt-in. The October 5 review fixes have not been test-executed at the user's instruction; prior passing counts do not validate the current changes. Passing fixture tests establishes expected behavior in the test harness; it does not establish safety, coverage, or finding quality on a live service.

## Implemented and locally validated

- Strict configuration, reviewed host/action/path policy, exclusions, expiry, DNS-pinned HTTPS collection, request/response bounds, cancellation, and invocation-time scope checks.
- PostgreSQL jobs with leases, fencing, recovery, retries, rate reservations, atomic observations, and workspace exports.
- Domain-list intake for submitted roots and a `research` worker path gated by both policy and `ENABLE_APPLICATION_RESEARCH`.
- Playwright exploration with same-origin routing, isolated contexts, challenge reporting, up to three configured accounts with user/admin roles and tenant labels, optional encrypted generated accounts, and an IMAP adapter. Configured role availability is part of coverage.
- Configured owner-resource access replay with owner/cross-account/repeat/negative controls. Every resource probe now requires a marker-based cleanup path and attempts deletion after every create attempt.
- Ownership replay reserves its eleventh request for cleanup and uses the observed 403/404 control. The live gateway journals marker cleanup before creation; the next authorized, identity-validated research job attempts pending cleanup before new probes. Assessment expiry permits a bounded cleanup attempt, while parent cancellation, revocation, policy change, and lease loss still stop it. Changed-policy or unavailable-owner debt remains pending for operator attention; this is not an independent cleanup scheduler.
- The scanner has an account-visible HackerOne company picker, all selected initially, with deselection and an explicit scope-confirmation step before database persistence. See [company import](COMPANY_IMPORT.md). This flow is implemented but not test-executed.
- Candidate discovery/admission libraries, Subfinder/CT/passive-DNS/Gitleaks adapters, methodology registry, web/API checks, finding/retest helpers, offline infrastructure analyzers, evidence utilities, and operations decision logic.
- 29 commit-pinned upstream source/data dependencies. Imported repositories are not executed just because they are pinned.

Local verification of the production-gate edit: `tsc --noEmit` passed. The default unit run passed 129 tests; `tests/dependencies.test.ts` fails on this share because git rejects the UNC checkout as dubious ownership, and the same 6 pin checks pass when that command sets `safe.directory` for the process only. Four Chromium browser tests passed against the injected lab, including marker cleanup when create omits the resource id. `npm run verify:local` passed 15 PostgreSQL tests, including the finding-actor guard, database kill switch, and dead-letter insert, then the fixture worker replay. Browser tests use real Chromium against an injected synthetic HTTP transport and a mocked mailbox. No research target, real account, external mailbox, or live Ollama process was used.
